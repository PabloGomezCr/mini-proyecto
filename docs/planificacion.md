# Planificación del proyecto

## Análisis del problema

La empresa necesita sustituir procesos manuales por una herramienta que organice la información de clientes, productos y proveedores. La solución debe permitir registrar, consultar, editar y eliminar datos desde una interfaz sencilla.

## Alcance

El proyecto incluye únicamente:

- Login.
- Dashboard.
- Administración de clientes.
- Administración de productos.
- Administración de proveedores.
- Persistencia con LocalStorage.
- Control de versiones con Git.

## Fuera del alcance

No se implementará:

- Backend.
- Base de datos externa.
- Registro de usuarios.
- Roles o permisos.
- Recuperación de contraseña.
- APIs.
- Reportes.
- Exportación de datos.
- Otras funciones no solicitadas.

## Distribución de dos días

### Día 1

- Analizar el problema y los requerimientos.
- Definir la estructura de carpetas.
- Crear la estructura HTML.
- Crear los estilos base.
- Implementar y probar el login.
- Crear la estructura del dashboard.

### Día 2

- Implementar el CRUD de clientes.
- Implementar el CRUD de productos.
- Implementar el CRUD de proveedores.
- Integrar LocalStorage.
- Ejecutar pruebas manuales.
- Revisar el historial de Git.
- Completar README y documentos.
- Realizar ajustes finales.

## Distribución del equipo

### Integrante 1

- Estructura HTML.
- Login.
- Dashboard.

### Integrante 2

- CRUD de clientes.
- CRUD de productos.

### Integrante 3

- CRUD de proveedores.
- LocalStorage.
- Documentación y pruebas.

La distribución es una propuesta. Todos los integrantes deben revisar, comprender y ser capaces de explicar la solución completa.
